Using the request and the exploration, explain the problem, the intended outcome, the scope, what
is explicitly out of scope, the affected areas, the risks and observable acceptance criteria.

Separate required work from optional follow-ups. Derived work must be necessary for an approved
behavior, an existing constraint or a concrete evidence-backed risk; explain that connection.
A possible future use or discovered improvement is not automatically in scope. Surface material
scope expansion for a decision instead of silently incorporating it.

Separate observed evidence, constraints and assumptions so later actors know what is settled and
what still needs confirmation. Reference the exploration's findings instead of repeating them;
investigate only gaps that affect scope or acceptance. List the questions specification and design
must answer, and put decisions only the user can make under `## Questions`.

This phase proposes: do not implement the change.
